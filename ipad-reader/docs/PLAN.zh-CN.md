# 页间开发规划

## 产品边界和协作分工

页间是供自己使用的原生 iPad 阅读器。阅读和写在书页上的体验优先；AI 必须带出处；3D 角色是可关闭的扩展。

Claude 负责房间、角色、材质、表情、动作与分镜；Codex 负责 SwiftUI 阅读界面、阅读引擎、PencilKit、数据保存、AI 检索与引用、导出、云编译和原生与场景间的连接。

## UI 组织

| 页面 | 布局与交互 |
| --- | --- |
| 书库 | 封面、搜索、最近阅读、导入；不以角色或场景作为启动前提 |
| 阅读 | 全屏暖纸背景，竖屏单页、横屏双页；青色顶栏与进度条覆盖正文，点击页面隐藏／恢复；目录与 AI／笔记按需打开 |
| 批注 | 原文和透明笔迹同一坐标系；单一笔图标进入／收起工具；连续跨页画布；钢笔、荧光笔、橡皮、撤销／重做、隐藏 |
| 笔记 | 来源、内容、原文跳转、编辑；以后增加笔记本／分区、标签和独立编辑页 |
| AI | 选择当前页／摘录／全书／笔记范围；回答、证据卡、点击回原文；保存回答时一起保存出处 |
| 导出 | 分开提供分享文件和可编辑备份，显示包含的内容与范围 |
| 读书房间 | 将来使用独立 WKWebView 页面，退出后暂停渲染 |

视觉与布局按用户提供的六张阅读器截图：整屏暖纸、棕色正文、章序与标题居中、紧凑青色工具栏、深灰目录与设置浮层。页面占满阅读区，界面显示／隐藏和打开面板不改变正文坐标；不绘制书封、书脊、纸张切口等外围实体书装饰。竖屏单页、横屏双页按宽高方向判断。图标动作至少约 44pt，唯一批注入口为笔图标。

左右页共用连续画布。一笔跨过中线仍是一个可编辑对象；竖屏显示同一对象在当前页的部分，橡皮和撤销均作用于整笔。新书无笔迹时可按视口排版，已有笔迹时保留原版式并统一缩放；不得在旋转时拆分笔画或让笔迹偏离原文。

## 里程碑与验收

### V0.1：UI 与 TXT 实现骨架（本次）

原生 SwiftUI UI；TXT 导入；实际测量分页；PencilKit 独立笔迹；引用和笔记定位；本地摘录问答演示；Markdown、透明 PNG、原生 JSON 备份；浏览器交互预览；GitHub macOS 构建。

验收：能打开示例与自己的 TXT，在指定页手写，离开再回来仍能编辑；缩放和换页没有串页；点击引用回到对应段落；导出并恢复书籍、笔迹、版式和笔记。

### V0.2：EPUB／PDF／网页基础阅读和完整导出（已实现）

可重排 EPUB 的 OPF／spine／nav／NCX 解析、正文和位图插图；PDFKit 解析＋Core Graphics 原页绘制；HTML／公开 HTTPS 文章的正文和可获取插图离线保存。三种格式接入统一双页笔迹画布、原文搜索、出处和 V3 备份。原生增加全书合成 PDF、仅笔迹 PDF 和原文件导出。详见 [格式实现说明](FORMATS.zh-CN.md)。

验收：原创 EPUB 的 manifest 与 spine 顺序不同时仍按 spine 阅读，插图有对应原文件；PDF 文字页和无文字页均可看，旋转和非零裁切正确；网页脚本不执行，原文及可取插图离线保留；原件与笔迹能随备份恢复，旧版备份仍可读。扫描内容目前提示尚需 OCR。

完整出版者 CSS、公式／表格、固定版式 EPUB、PDF 双指缩放／文字选中、带登录态的动态网页和小说章节采集仍为后续工作。

### V0.3：带证据的真实 AI

正文按章节、段落和文本范围建立索引；手写与扫描内容使用 Vision OCR；先用本地全文／关键词检索，再视需要加向量索引。上下文只传用户选择的范围与检索出的片段。

模型入口定义为协议，可接个人指定的服务；密钥保存在 Keychain。模型输出结构化回答和证据 ID，由程序检查 ID 存在、证据属于当前书籍后再展示跳转。无证据时显示没有找到依据。保存回答时保存问题、回答、证据版本和锚点。

验收：提问后得到与原文相符的解释；每条引用真实存在且可定位；跨章节跳转准确；断网可继续阅读和批注；模型失败不丢本地数据。模型供应商、费用和服务地址由后续实际选择决定。

### V0.4：完整 EPUB 排版、重排迁移和在线小说

评估成熟 EPUB 引擎，优先检查 Readium Swift Toolkit 的分页、定位和资源模型；正文与 Apple Pencil 透明层使用可控的共同容器。TXT 使用段落＋UTF-16 范围；EPUB 使用资源 href＋引擎定位符／CFI＋文本引文；PDF 使用页号＋页内归一化矩形。

网页文章通过分享扩展／URL 导入，保存正文和来源时间；在线小说按章节快照保存，明确登录、动态加载及源站变化不属于普通静态正文导入。

验收：重排前后书签、文字笔记和引用能回到原文；已有手写保留原版式，尝试迁移的笔迹能单独复核；导出备份包含网页正文快照，离线仍能读。

### V0.5：3D 书房与 Blender 角色

先完成离线 WKWebView 自定义资源协议和消息接口，再接角色状态、表情、动作和物理。进入书房不会影响书籍或笔迹保存；退出后渲染暂停。场景由 Claude 在既定契约内迭代。

## EPUB／TXT 手写重排方案

不能只保存屏幕坐标，也不能宣称按段落偏移就能自动迁移任意圈画。

每份批注保存：书籍内容哈希、原文件／章节、原文锚点、前后文引文、原版式版本、逻辑页尺寸和可编辑笔迹。批注同时引用原版式快照，确保任何时刻都能原样回看。

重排后分三种处理：

1. 文字摘录和文字笔记按原文锚点重新定位。
2. 单行划线、局部圈画先关联文本矩形或字符范围，再按新字形位置重建。
3. 跨段箭头、复杂草图、页边手写保留在原版式，并提供人工确认的迁移；不会在位置不确定时静默漂移。

当前 V0.1 用明确的锁定版式作为第一步。跨版本备份、迁移算法和迁移撤销是后续独立功能，不以普通缩放冒充重排。

## 数据与备份

生产版目标：书籍原文件、解析正文、定位索引、阅读位置、版式版本、可编辑笔迹、文字笔记、OCR、AI 回答、证据和资源清单分别管理。使用版本化容器和校验值，恢复先校验，再原子替换；书籍内容更新需建立新版本。

当前原生 JSON V3 用 `engine=native-pencilkit-v3`、逻辑页尺寸与 `spreadDrawings` 保存完整 PKDrawing；浏览器 schema 3 使用 `spreadInk` 与 `pageSize` 保存 SVG 点列。两者均向后读取各自 V1／V2 备份，保留旧排版并迁移到共享画布。当前没有跨引擎恢复能力。两者都必须保留原文和位置，PNG／打印 PDF 是分享产物，不是可编辑备份。

## 编译和安装

Windows 编写代码，GitHub macOS runner 生成工程并编译。编译、签名、安装是三个独立步骤：未签名 IPA 先通过构建检查，随后选择免费个人签名和 Windows 侧载途径进行实机验证。

用户提供的设备条件是 A16 iPad／iPadOS 26.7。此版本号、具体机型、Apple Pencil 型号、安装工具兼容性与续签行为还未实测，不能用“构建成功”代替兼容性验证。最低部署目标设为 iPadOS 17，最终兼容结论以实机检查为准。
